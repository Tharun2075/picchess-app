# Decisions

## Ticket 01: play from FEN
- Pieces: cm-chessboard's bundled sprites are CC BY-SA 3.0 (Cburnett) and CC BY-NC-SA 4.0 (Staunty), so neither is shipped. We use Chessnut (Apache-2.0), 12 SVGs from lichess's copy, merged into one sprite at app/vendor/cm-chessboard/assets/pieces/chessnut-sprite.svg. Licence text in app/vendor/chessnut/LICENSE.
- Trimmed cm-chessboard to the core plus the Markers extension (MIT); dropped arrows, accessibility, persistence and others to keep it small.
- `assetsCache: false`: with the cached sprite, pieces did not render in headless Chrome; referencing the sprite by URL did.
- Promotion picker is our own HTML overlay instead of the library's dialog (which needs its own sprite pieces).
- A FEN with only the placement field is accepted and completed with `w - - 0 1`; whitespace is normalised.
- Invalid FEN never changes the running game.
- Game over disables move input; Undo re-enables it.
- Proof screenshot is taken at 500x1000 because headless Chrome will not go narrower than about 500px; the layout is fluid for 360px phones.
- Headless Chrome with a fresh --user-data-dir hung in this environment; the default profile worked.

## Ticket 02: Stockfish top 3
- Engine: Stockfish 19.0.1 lite single-threaded WASM, unmodified, in app/engine/ (stockfish-19-lite-single.js sha256 ccb130d7…, .wasm ee4f115b…, COPYING 0b383d5a…; full hashes in SOURCE.md). Upstream and GPLv3 notice in app/engine/SOURCE.md. Reached only through a Web Worker speaking UCI text. No JS fallback engine and no fake moves.
- Single-threaded build chosen because it needs no SharedArrayBuffer / COOP-COEP headers, so plain `python3 -m http.server` works.
- Search settings: MultiPV 3, `go movetime 1500`; `ucinewgame` before each search (positions are unrelated jumps, so no stale hash).
- Stop-then-go handshake: a new position sends `stop`, waits for that search's `bestmove`, then starts the next. Output of a stopped search is ignored.
- `info` lines with lowerbound/upperbound, `info string` and currmove lines are ignored; only exact scores are shown.
- Eval is always from White's point of view (converted from the side to move), labelled in the UI. Format +1.2, -0.4, M3, -M2.
- Engine hints toggle is stored in localStorage (`picchess.hints`, default on). When off, no search is requested and a running one is stopped. The worker is only created when hints are on.
- If the worker or WASM fails: "Engine unavailable" is shown and the board stays playable.
- Arrows: best move strongest green, then amber, then grey; drawn in our own SVG overlay (cm-chessboard's arrows extension was trimmed in ticket 01).
- Proof: tools/proof02.mjs drives a headless Chrome over CDP; output in docs/proof-02-stockfish-top3.txt/.png.

## Ticket 03: board editor
- The editor holds its own position copy; `game` is replaced only by "Play this position" (which resets history to the new start). Cancel discards the copy.
- Model in app/lib/position.js is immutable: every function returns a new object. Board is a 64-array in FEN order.
- Castling: rights are auto-removed when king/rook leave their home squares and never auto-ticked; the user ticks them. toFen re-checks, so an impossible right cannot reach the FEN.
- En passant: offered only if the side to move has a pawn that can capture there and the squares behind are empty.
- Validation also rejects more than 8 pawns per side (not required, but impossible).
- Tools: "Drag" (cm-chessboard move input, any piece anywhere), a piece or eraser (square-select tap). Tapping a square already holding the selected piece removes it.
- "I play" sets only the board orientation; it is not part of the FEN.
- Halfmove/fullmove counters are not edited: written as 0 and 1.
- Proof: tools/proof03.mjs (CDP, own-browser) -> docs/proof-03-board-editor.txt/.png (+ -editing.png). Drag itself was not automated.

## Ticket 04: PGN, PWA, static hosting
- PGN via chess.js; headers Event/Site/Date/Result plus SetUp/FEN only for custom starts. Players are "?" (no name entry yet). Import takes PGN or a bare FEN; a failed import leaves the running game untouched (Game.loadLine).
- Service worker: cache-first for same-origin GETs, `ignoreSearch` so `?fen=` URLs work, navigation falls back to the cached index.html, skipWaiting + clients.claim. No runtime caching of anything else; no network calls to other origins (CSP `connect-src 'self'`).
- Cache name `picchess-<12-hex sha256 of all precached files>`, written by tools/stamp-sw.mjs into a marked block of sw.js; a test fails when stale, so a deploy cannot ship an old cache name by accident. Precache = every file in app/ except sw.js and _headers.
- Icons generated by stdlib Python (checkerboard + green dot, PNG 180/192/512 + maskable + SVG); placeholder art.
- CSP allows 'unsafe-inline' for styles only (cm-chessboard sets style attributes); scripts are 'self' + 'wasm-unsafe-eval'.
- COOP/COEP are commented out in _headers because the engine is single-threaded and they would break nothing now but add risk.
- vercel.json sits at repo root with outputDirectory "app"; Cloudflare is configured in its dashboard (build output dir app).
- Offline proof is desktop headless Chrome via CDP (own-browser), same-origin http://127.0.0.1 (a secure context for service workers).

## Ticket 05: image input + grid finding
- Finder: own code, gradient projection over candidate (x, y, size) with a checker-pattern check; coarse-to-fine on 256 then 512 px maps. Idea from tensorflow_chessbot (line finding); no code copied. LiveChess2FEN (GPL) was not looked at or copied. No OpenCV.
- Confidence is a blend of edge and checker agreement; it did not separate the 3 misses, so the UI always shows the overlay and corner dots instead of auto-trusting.
- Below 0.35 confidence a centred default box is shown with the corners to drag.
- Downscale to 1024 px max in a canvas; no upload, no network.
- Test fixtures: 200 synthetic PNGs at 48 colours (3.3 MB) to keep the repo small; decoded by a small pure-JS PNG decoder in tests/helpers/png.mjs.
- Pieces for synthetic renders are the vendored Chessnut SVGs (Apache-2.0) rasterised in headless Chrome (no cairo here); cm-chessboard's own set is not used.
- "Use this grid" opens the editor with an empty board (recognition is tickets 06-08). `?scan=<relative url>&bottom=w&turn=w` auto-loads a same-origin image for the proof.
- Sample image app/samples/sample-phone-green.png is fixture 005.

## Ticket 06: screenshot dataset
- Positions come from own code (random pseudo-legal playouts, sparse random endings, the start position). python-chess is not used at all, so there is no GPL dependency even for development. Playouts ignore check, castling and en passant.
- Piece sets (data/SOURCES.md): Chessnut (Apache-2.0), plus sets drawn by own code: glyph (Apple Symbols chess glyphs), letters (Arial Bold on discs) for training; geo (own shapes, CC0) and serif (Times New Roman letters in rounded squares) held out. No CC-BY-SA or GPL set was needed. Font-derived images are local training data only and never enter app/. Only four-to-five sets exist: real coverage must come from data/real_screens/.
- Held-out split changes themes AND piece sets together (4 themes, 2 sets). A separate val split keeps the training themes and sets, so a gap between val and heldout measures generalisation.
- Tiles are cut from the saved (already compressed, blurred, scaled) image using the known board box, in FEN order, with orientation handled at slicing. Stored as 32x32 grey bytes in one file per split to avoid 1.3 million small files.
- Empty cap: every piece tile kept; per board at most max(piece count, 8) empties, seeded. Result is 50.1% empty, below the 60% limit. Full 64-square labels remain in labels.csv.
- Determinism: each board is seeded by "seed/split/index" so multiprocessing order does not matter; tests check byte-identical files.
- Tests are Python unittest, called from node via tests/dataset.test.mjs; skipped (with reason) when .venv is missing so `npm test` still runs on a clean checkout.
- data/ is ignored except data/real_screens/README.md, labels.csv header and data/SOURCES.md; real screenshots stay ignored.
- No VLM or external API anywhere; the classifier trained later ships as ONNX in the browser.

## Ticket 07: screenshot square classifier
- Own model, not fenshot: val 99.67% square / 90.0% board vs fenshot 95.0% / 51.1% on the same renders. Fenshot's code and class order are adapted (MIT, credited); vendor/fenshot trimmed to 1.3 MB and its .git removed.
- Licence audit of lichess piece sets read from lila COPYING.md: all allow derivatives (Apache-2.0, CC0, MIT, CC BY 4.0), none dropped. Training-only, never shipped.
- fp32 ONNX shipped (1.29 MB). The int8 dynamic-quantised file needs ConvInteger, which onnxruntime CPU cannot run, so it cannot be verified or used; the fp32 file is already small.
- Training is deterministic: rerunning ml/train_squares.py on seed 7 gave a byte-identical model. An earlier model (plain augmentation, val 99.83% / 94.25%) was better on val but its training code was overwritten by later edits, so it was not shipped; the reproducible heavy-augmentation model was.
- Held-out sets: celtic (MIT), papercut (CC BY), geo (own). Not part of acceptance; reported as a known limit.
- Generalisation probe (not shipped): spatial excluded -> 98.5% / 28.8% on spatial; purple excluded -> 99.5% / 78.4%.
- Bug fixed: stray local "import json" in train_squares.py after adding --exclude-set/--exclude-theme.
- No browser proof for this ticket; docs/screenshot.png stays the ticket 06 proof.

## Ticket 08: screenshot to FEN in the browser
- onnxruntime-web, WASM backend, one thread: runs on every browser including iOS Safari, needs no cross-origin-isolation headers (threads need COOP/COEP, which static hosts and the service worker make awkward). The model is 1.2 MB with 64 tiny tiles, so a read takes about 50 ms; threads or WebGPU would add risk for no visible gain.
- Lazy ML cache: the 12 MB wasm and the model are fetched only on the first scan and kept in a second service-worker cache (ML_CACHE), so the normal app install stays small and chess play offline is unaffected.
- No server: picture, tiles and model all stay in the page. Nothing is uploaded.
- "Check the board" is always shown after a read: the board editor opens prefilled, unsure squares are outlined, and Play stays locked until the user confirms. Unseen piece art is about 90% per square, so a silent result would be wrong.
- Bottom colour is guessed from pawn/king positions and can be switched in the editor.
- Proof: real browser at 390 px, held-out fixture 01 (totoy, purple, Black at bottom): 0 of 64 wrong, see docs/proof-08-screenshot-to-fen.txt. tools/serve.mjs is a static server with correct MIME types; tools/proof08.mjs drives the proof.
